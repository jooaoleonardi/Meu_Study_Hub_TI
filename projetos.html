O problema

O repositório organiza bem o material, mas um recrutador ou avaliador que recebe o link precisa navegar por pastas e READMEs para entender quem eu sou e o que já produzi. Faltava uma porta de entrada visual, de leitura rápida, que resumisse o portfólio e apontasse para cada parte do repositório.

A solução

Um site estático publicado com GitHub Pages a partir da branch main, com páginas para perfil, carreira, projetos, disciplinas, versionamento e entregas.

Decisões de arquitetura

  • Sem framework e sem build. O GitHub Pages publica os arquivos exatamente como estão no repositório.
  • Tema claro e escuro. Segue a preferência do sistema, com botão para alternar.
  • Responsivo. Funciona do celular ao desktop, com menu recolhível.
  • Acessível. HTML semântico, link para pular ao conteúdo, foco visível e respeito a prefers-reduced-motion.
  • Versionado. Cada versão tem entrada no CHANGELOG e tag Git.

Força Bruta em Hash SHA-256

Status
Concluído
Período
nov/2024
Origem
Atividade da graduação em Ciência da Computação
Stack
Python 3: hashlib, itertools, multiprocessing

O problema

Uma função de hash como a SHA-256 é de mão única: a partir da string é fácil calcular a hash, mas a partir da hash não há como voltar. Quando o conjunto de entradas possíveis é pequeno, porém, dá para testar todas. O desafio foi encontrar a string de exatamente 7 caracteres, só com letras de a a z, que gera uma hash conhecida: 26⁷ = 8.031.810.176 combinações.

A solução

  1. Geração sob demanda. itertools.product gera as strings uma a uma, sem guardar 8 bilhões de candidatos na memória.
  2. Divisão pela primeira letra. O espaço de busca vira 26 tarefas, uma para cada letra inicial.
  3. Execução em paralelo. Um multiprocessing.Pool com núcleos − 1 processos distribui as tarefas, deixando um núcleo livre para o sistema.
  4. Comparação. Cada processo calcula a SHA-256 de cada candidato e compara com a hash alvo.
                       ┌─ processo 1 ─ testa a?????? ... ─┐
hash alvo ──► Pool ────┼─ processo 2 ─ testa b?????? ... ─┼──► string encontrada
(26 tarefas)           └─ processo N ─ ...               ─┘
TecnologiaPor que foi escolhida
hashlibImplementação padrão e otimizada da SHA-256 no Python
itertools.productGera o produto cartesiano das letras sem ocupar memória
multiprocessingUsa todos os núcleos de verdade, sem a limitação do GIL que afeta as threads

Validação

A validação gera a hash de palavras conhecidas de 4 letras (a primeira combinação, a última e uma do meio) e confere se a busca devolve exatamente a palavra de origem. A string de 7 letras não é publicada, para não entregar a resposta do desafio.

[OK] hash de 'aaaaaaa' confere com o enunciado
[OK] aaaa -> aaaa (0.18s)
[OK] zzzz -> zzzz (0.16s)
[OK] java -> java (0.20s)
Todos os casos passaram.

Aprendizados

O projeto mostra na prática por que senhas curtas e com poucos tipos de caractere são frágeis: com 7 letras minúsculas, um computador comum testa todas as combinações. Também mostrou a diferença entre threads e processos no Python e como dividir um problema grande em partes independentes para usar todos os núcleos.

Próximos passos

  • Parada antecipada: encerrar o pool no primeiro acerto, hoje ele espera as 26 tarefas.
  • Máquinas de um núcleo: usar max(1, cpu_count() - 1).
  • Medir o tempo total e a taxa de hashes por segundo com 1, 2, 4 e N processos.

Como adicionar um projeto

  1. Criar a pasta em minúsculas com underscore: nome_do_projeto/.
  2. Copiar o modelo de README de _templates/modelo_projeto.md e preencher problema, solução, stack e execução.
  3. Adicionar a linha no índice de projetos.
  4. Commit no padrão: feat(projetos): adiciona projeto nome_do_projeto.
