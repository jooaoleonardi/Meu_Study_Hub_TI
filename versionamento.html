Convenção de commits

TipoQuando usarExemplo
docsDocumentação, README, resumosdocs(seguranca): adiciona resumo de criptografia
featNova entrega, projeto ou materialfeat(bootcamp): adiciona entrega da fase 1
fixCorreção de conteúdo ou linkfix(readme): corrige link da arvore de pastas
choreOrganização e manutençãochore(estrutura): arquiva disciplinas do modulo 1

Formato: tipo(escopo): descrição. Commit pequeno e frequente vale mais que commit grande e raro: dez commits ao longo do mês contam uma história de consistência.

Ciclo do dia a dia

Quatro comandos cobrem a rotina:

  1. status mostra o que mudou.
  2. add prepara as mudanças.
  3. commit registra com mensagem padronizada.
  4. push envia para o GitHub.
git status
git add -A
git commit -m "docs(seguranca): adiciona resumo de criptografia"
git push

Versionamento semântico e tags

As versões seguem o versionamento semântico e o formato Keep a Changelog. Cada versão do CHANGELOG corresponde a uma tag Git anotada, o que permite voltar a qualquer ponto da história do portfólio.

git tag -a v1.2 -m "Versao 1.2"
git push origin v1.2
git tag -n

Checklist antes de cada commit

  • Os nomes de arquivo seguem o padrão disciplina_tipo_tema.extensao?
  • O arquivo está na pasta correta (Atividades ou Anotações)?
  • Algum README de índice precisa ser atualizado?
  • A mensagem de commit segue tipo(escopo): descricao?
  • Nenhuma credencial ou dado sensível está sendo commitado?
